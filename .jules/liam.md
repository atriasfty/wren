## 2024-08-01 - Express Server Stack Trace and Information Leakage
**Vulnerability:** The Express server lacked proper error handling, which could lead to stack traces being leaked to clients on errors like malformed JSON requests or unhandled exceptions. Additionally, the default Express server configuration set the `X-Powered-By: Express` header (or a custom one), and setting headers per request rather than globally was less robust.
**Learning:** By default, Express reveals server implementation details through headers and stack traces on 500 errors in development or unhandled error situations. `express.json()` throws a SyntaxError with status 400 when it encounters invalid JSON, which, if not caught specifically, can result in the default HTML error page (including stack trace) being sent. Catch-all error handlers must use 4 arguments `(err, req, res, next)` to be recognized as error-handling middleware by Express. It is also important to check `res.headersSent` before sending an error response to avoid attempting to send headers after they have already been sent.
**Prevention:** Always add a catch-all error handling middleware `(err, req, res, next)` at the end of the route definitions to return a generic 500 response without leaking internal state. Add a specific error handler immediately after `express.json()` to catch `SyntaxError` and return a generic 400 JSON error. Globally disable `x-powered-by` via `app.disable('x-powered-by')` at the beginning of the server setup.
