## 2025-02-28 - Unhandled Exception Stack Trace Leaks via Express error handling
**Vulnerability:** The API server missed a global error handler for catch-all synchronous errors, and also didn't explicitly handle `SyntaxError` from Express JSON body parsing (which sends a 400 with a stack trace in development, or swallows the JSON response in unexpected ways exposing defaults).
**Learning:** In Express, catching `SyntaxError` immediately after `express.json()` prevents the framework from propagating JSON parsing errors that would otherwise expose HTML stack traces or ugly default payloads to the client. Additionally, a catch-all route at the bottom is necessary for handling unhandled controller/middleware exceptions without leaking server stack traces in non-production environments.
**Prevention:** Always place a 4-argument error handler (`(err, req, res, next)`) immediately after body-parsing middleware to catch malformed payloads, and always place a final 4-argument catch-all error handler at the end of the route definitions.
