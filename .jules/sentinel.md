## 2024-05-31 - Missing Express Error Handlers Leak Stack Traces
**Vulnerability:** Express API Server was missing custom error handlers, allowing malformed JSON payloads to trigger a SyntaxError and expose detailed stack traces in HTML responses. The server was also missing a global catch-all error handler at the end of routes to catch uncaught application errors.
**Learning:** By default, Express returns full stack traces in development/certain environments or leaks generic HTML error pages when errors hit the default handler. This codebase requires explicit error handling inside `server.js` directly after `express.json()` to properly return 400 JSON and at the end of routing to securely handle 500 exceptions, because errors from middleware skip normal route handlers.
**Prevention:** Always add a specific handler for `SyntaxError` after `express.json()` ensuring `next(err)` is called for non-matches, and a global catch-all error handler at the end of the Express application route configuration. Also globally apply `app.disable('x-powered-by')` once on the Express app instance.
