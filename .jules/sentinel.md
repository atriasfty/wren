## 2026-07-28 - Express.js JSON parsing errors leaking HTML stack traces
**Vulnerability:** Express.js's built-in `express.json()` middleware throws a `SyntaxError` with a 400 status code when it receives malformed JSON. If this specific error is not caught by a custom error handler immediately after the middleware, Express's default error handler catches it and sends an HTML response containing the full error stack trace back to the client, leaking internal server paths and implementation details.
**Learning:** In Express, a global error handler at the end of the route definitions is not always enough to prevent information leaks if earlier middleware (like body parsers) throw specific errors that aren't gracefully caught and transformed.
**Prevention:** Always place a custom error handler immediately after `express.json()` that specifically checks for `err instanceof SyntaxError && err.status === 400 && 'body' in err` to catch JSON parsing failures, returning a generic 400 JSON response and calling `next(err)` for non-matching errors. Furthermore, always implement a global catch-all error handler at the route boundary that guarantees a generic 500 JSON response instead of the default HTML format.
