## 2024-10-24 - API Error Handling & Stack Trace Leaks
**Vulnerability:** The Express application lacked generic exception handlers and did not safely intercept `SyntaxError` from `express.json()`. This allowed malformed JSON requests to expose default Express HTML stack traces and unhandled exceptions to crash or leak server internals to the client.
**Learning:** In standard Express.js routing, `app.use(express.json())` throws a raw `SyntaxError` when parsing bad JSON, which bypasses normal application flow unless explicitly caught by an error middleware immediately following it. Furthermore, any unhandled promise rejection or synchronous error in a route without a global error boundary will either hang the request, drop the connection, or leak stack traces depending on the Express version and configuration.
**Prevention:** Always mount a custom error handler directly after `express.json()` to capture 400 SyntaxErrors. Always ensure the root server setup terminates with a catch-all global error handler that returns a generic JSON 500 response (and internally logs the actual error). Additionally, remove the `X-Powered-By` header using `app.disable('x-powered-by')` once on the application instance rather than a per-request middleware.
