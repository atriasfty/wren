## 2025-02-12 - [MEDIUM] Prevented stack trace leaks in Express JSON parser
**Vulnerability:** When `express.json()` receives a malformed payload, it throws a `SyntaxError` with status 400. Without a custom error handler immediately following it, Express's default error handler catches it and responds with a full HTML page containing the error stack trace, which leaks internal server implementation details to a potential attacker.
**Learning:** `body-parser` (used internally by Express) intentionally passes errors down to the `next()` middleware to allow the application to handle them. We must explicitly catch `err instanceof SyntaxError` with a 400 status to prevent this leakage. We also need to be careful to `next(err)` for non-matching errors so we don't swallow application errors.
**Prevention:** Always add a custom error handler immediately after `express.json()` or any body parser middleware in Express applications to sanitize parsing errors before they bubble up to the default error handler.
